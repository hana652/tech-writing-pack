# AI日本語文体 検出・修正ルールセット v0.3

v0.1（辞書的誤用リスト）・v0.2（文体チックリスト）を統合した完全版。検体3本（Zenn技術記事・NotebookLM長文ポスト・説明術エッセイ・Design.md技術記事）の実地テスト結果と、Claude自身の生成傾向の自己分析を反映した。

構成はPart A（コロケーション・語彙リスト）とPart B（構文・談話リスト）の2部。共通原則と密度基準総表、セルフチェック指示文、lint実装優先順位を併録する。

---

## 0. 共通原則

### 0-1. 誤りではなく密度の問題

AI文体の違和感の主因は、辞書的な誤用ではない。単体では正しい日本語の技法・語彙が、人間の書き手の実測上限を超える密度で出現することにある。したがって本ルールセットの大半は「禁止」ではなく「上限回数」で規定する。上限を1〜2回残すのは、技法自体は有効であり、全滅させると文章が死ぬため。

### 0-2. 発生機序の由来マップ

癖の由来は2系統ある。対策プロンプトを書く際はどちら由来かで打ち手が変わる。

指示由来（AIが受けている執筆指示の過剰発火）:
- 箇条書き・装飾の抑制指示 → 構造を対比構文「AではなくB」で代替する癖
- 簡潔さへの最適化 → 切り詰め表現（だけ・たった・一択）、断片化、体言止め
- 比喩・例え話の許可 → メタファーの全編回収、メタファー系統の乱立
- 読者配慮・温かいトーン → メタ談話予告、自問自答、語りかけ定型
対策: 「比喩は1記事1系統まで」「対比構文は2回まで」のように、指示側の許可に数量制限を付ける打ち消しプロンプトが効く。

学習由来（英語修辞の転移）:
- It's not X, it's Y → 「AではなくB」構文
- rule of three → 三連反復（トリコロン）
- em-dash → 「——」の挿入・言い換え多用
- アフォリズム締め → 警句化した常体一文、円環構成
対策: 打ち消しプロンプトに加え、生成後の機械検出が確実。転移は無自覚に起きるため指示だけでは抑まりきらない。

対比構文が全検体で最頻・最重度（16回/14回/6回、人間の実測上限は長文1本あたり2〜3回）だったのは、指示由来と学習由来の両方から供給される唯一のパターンであるため。lint優先度も最上位。

### 0-3. レジスター別の適用強度

- 技術記事（Zenn等）: 全ルール標準適用
- SEO記事・オウンドメディア: 標準適用。ただし媒体トーンが口語寄りの場合、Part Aの密度閾値を1.5倍に緩和
- クライアント納品文書・提案書: 全ルール厳格適用（上限回数を半分に）
- X・note等のバズ文体: 技法の使用自体は前提とし、密度超過のみ判定（各上限を2倍に緩和して適用）

## Part A: コロケーション・語彙リスト

### A-1. 転用監視動詞

身体感覚・生活感覚の動詞を抽象名詞・技術名詞に結合させる転用。1つずつは自然だが密度で崩壊する。

監視リスト（五十音順）:
埋まる（キャパが埋まる）／落ちる（精度が落ちる以外の転用）／回す・回る（好循環が回る、ノートが回る）／効く／食う・食われる（トークンを食う、時間を食われる）／こける／固まる（人が固まる）／刺さる／渋滞する（言葉が渋滞する）／育つ・育てる（ノートが育つ）／事故る／ずれる・ズレる（説明がズレる）／溶ける・溶かす（時間を溶かす）／詰む／潰す（質問を潰す）／流す・垂れ流す（時系列で垂れ流す）／逃がす（詳細を逃がす）／握る／剥がす／化ける／張る／ブレる（判断がブレる）／古びる（ドキュメントが古びる）／蒸発する（文脈が蒸発する）／溺れる（資料の山に溺れる）／汚れる（コンテキストが汚れる）／彷徨う（ネットの海を彷徨う）

代表的な書き換え:
- 時間を溶かす → 時間を取られる・費やす
- トークンを食う → トークンを消費する
- 判断のブレ → 判断の一貫性が失われる・判断が安定しない
- コンテキストが汚れる → 実装の詳細が混入する
- 〜に効く → 〜に有効・〜に役立つ・〜で価値を発揮する
- 質問を潰す → 質問を解消する
- 文脈が蒸発する → 文脈が失われる
- 詳細を逃がす → 詳細を切り出す・移す
- 死に情報になる → 参照されない情報になる

密度ルール:
- 転用使用は本文1,000字あたり1回まで
- 同一動詞の転用は1記事1回まで（「効く」を2回使わない。タイトルでの使用も1回に数える）
- 見出し・リード文・結論段落・箇条書き項目名では0回

### A-2. 比喩名詞・基幹メタファー

検出済みの頻出比喩名詞:
ドミノ／弾／武器／地図・見取り図／攻略本／装置／エンジン／温床／居場所／羽目／倉庫／迷路／景色／解像度／手触り・肌触り／輪郭／熱量／土足／過積載／交通整理／ZIP・USB・拡張子・タブ等のPC比喩／和平条約・宣戦布告等の戦争比喩／下ごしらえ・全部盛り等の料理比喩

ルール:
- 基幹メタファー（記事の骨格として反復する比喩）は1記事1系統まで。記事の主張に直結する系統だけを残し、他は事実記述に開く
- 基幹メタファーの反復回数は3回まで。AIは比喩を立てると律儀に全編で回収し続けるが、人間はもっと使い捨てる
- 単発比喩（1回きりの直喩・隠喩）は1,000字1回まで
- 滲む・息づく・紡ぐ・物語る（擬人）・立ち上がる（抽象）は密度に関係なく実用文では全面禁止（v0.2から継承）

### A-3. 強調語・程度副詞インフレ

監視リスト:
決定的／本命／肝心／一択／最大／最強／圧倒的／劇的／爆速／神（神機能・神すぎる）／驚くほど／とてつもなく／かなり／正直／ちゃんと／地味に／控えめに言って

ルール:
- 同一強調語は1記事1回まで（検体実測: 「決定的」2回、「かなり」5回、「効く」3回はいずれも読者に型を気づかせる水準だった）
- 文頭の「正直、」は1記事1回まで。「正直けっこう」等の口語副詞の重ね使いは禁止
- 「控えめに言って〜」等のネットミーム定型は媒体がバズ文体の場合のみ1回許容

### A-4. 慣用句の混交・破損（旧v0.1 Type 4）

固定文字列で機械検出可能なため付録として維持する。

| NG | OK | 混交元 |
|---|---|---|
| 頭ひとつ飛び出る | 頭ひとつ抜ける | 頭ひとつ抜ける × 飛び抜ける |
| 的を得る | 的を射る | 的を射る × 当を得る |
| 汚名挽回 | 汚名返上／名誉挽回 | 汚名返上 × 名誉挽回 |
| 二の舞を踏む | 二の舞を演じる | 二の舞を演じる × 二の足を踏む |
| 足元をすくわれる | 足をすくわれる | 足をすくう × 足元を見る |
| 熱にうなされる | 熱に浮かされる | 熱に浮かされる × うなされる |
| 押しも押されぬ | 押しも押されもせぬ | 短縮破損 |
| 論戦を張る | 論陣を張る | 論陣を張る × 論戦を交わす |
| 火蓋が切って落とされる | 火蓋が切られる | 火蓋を切る × 幕が切って落とされる |
| タスクを譲渡する | タスクを引き渡す・委譲する | 語の適用範囲逸脱 |
| 〜のみに徹底させる | 〜に徹する・専念させる | 徹する × 徹底させる |
| 〜を振り当てる | 〜を割り当てる | 割り当てる × 振り分ける |

## Part B: 構文・談話リスト

### B-1. 対比構文「AではなくB」【最優先】

全検体で最頻・最重度。指示由来（箇条書き禁止の代替構造）と学習由来（It's not X, it's Y）の二重供給。

検出パターン: ではなく／ではありません。／じゃない。／じゃなくて／〜わけでも〜わけでもない／〜というより

上限: 1記事2回。バズ文体でも4回。

書き換え手順:
1. B（肯定側）だけで主張が立つか確認する。ほぼ立つ。
2. 「評価を決めるのは、作業ではありません。成果です」→「評価を決めるのは成果です」のように肯定形に畳む。
3. Aの否定が本当に必要な場合（読者の誤解が実在する場合）のみ対比を残す。
4. 冒頭と結末で同じ対比を反復する円環構成（B-8）と併発しやすいので同時に確認する。

### B-2. 三連反復（トリコロン）

同型の語句・文を3つ並べる。rule of threeの転移。検体②で7セット検出。

検出パターン: 同一文末・同一語尾の3連続（「〜怖い。〜怖い。〜怖い。」「〜でいい。〜でいい。〜でもいい。」「〜どうしよう。」×3）

上限: 1記事2セット。残す場合も完全同語尾は崩す（3つ目だけ形を変える、2連や4連を混ぜる）。

### B-3. 断片化・体言止め・切り詰め

- 体言止め: 1記事3回まで。2文連続の使用は禁止。4連（「家族との夕食。我慢していた趣味。学び直し。副業への挑戦。」）は読点接続か「〜など」に畳む
- です・ます基調中の常体短文（「コードは書かない。」）: B-10で処理
- 切り詰め表現（だけ・たった・一択・これだけ・〜に集約されます・2つだけ）: 1記事2回まで。数を絞る訴求はまとめ章に集約する。全章で使うと単位が薄まる

### B-4. 指示語圧縮

検出パターン: 「と、それを」「と、その」「それを〜する方法」

書き換え: 指示語を名詞に戻し、動詞を目的語に合わせて選び直す。「その構成と、それを1コマンドで組む方法」→「その構成の中身と、構成を1コマンドで組み立てる方法」

### B-5. ダッシュ「——」

挿入・言い換え・余韻のいずれの用法でも上限は1記事2回。em-dashの転移で、ChatGPT系の生成文で特に高密度（検体①で10回超）。挿入は括弧か読点に、言い換えは「つまり」に、余韻は句点に開く。

### B-6. メタ談話予告・自問自答

本題の前に「今から大事なことを言う」と予告する文。読者配慮指示の過剰発火。

検出パターン: ここが〜なところです／いちばん大事な話をします／〜の話をさせてください／お気づきでしょうか／種明かしをすれば／冷静に考えて〜ないですか／するとどうなるか？／この章の最後に伝えたいことがあります

上限: 1記事1回。残りは削除して本題から直接入る。予告文の削除は情報を1つも失わない。

### B-7. 定型句

| 定型 | 上限 | 書き換え |
|---|---|---|
| 〜は別の話でした・別の話だ | 0回 | 何が課題かを具体に書く |
| 〜のがコツです・ポイントは〜こと | 1回 | 〜が重要です・〜してください |
| 〜んです・なんです・なんですよね | 2回 | です。に畳む。「ですよね」の同意圧は0回 |
| 〜してくれます（ツール擬人化） | 2回 | 〜されます・〜できます |
| だから伝わる。等の同文リフレイン | 1回 | 2回目は表現を変える |
| 鍵となります・重要な役割を果たします | 各1回 | 具体的な機能・効果を書く |
| 〜を可能にします | 0回 | 〜できるようになります |

### B-8. 構成レベルの癖（円環・同型反復）

- 円環構成: 冒頭の主張文を結末でほぼ同文で反復して閉じる（検体①の「時短ツールではありません」）。AIの「きれいに閉じる」癖。結末では冒頭の主張を別の角度・別の表現で回収する
- 同型締め: 各節の末尾が「これが1つ目の違いだ」「これが2つ目の違いだった」型の機械的反復。締め方は節ごとに変える
- リードのテンプレ化: H2直下リード必須ルールを守った結果、全リードが「〜を整理します」「〜に触れておきます」型で同型化する（検体③で確認。ルール遵守が新しい癖を生む例）。リード文の述語を節ごとに変える。予告型（〜を説明します）だけでなく、問題提起型・結論先出し型・場面提示型を混ぜる

### B-9. 談話接続（両方向）

AI文体は接続の欠落と過剰の両方向に振れる。検体で両タイプを確認済み。

欠落型（Zenn記事型）:
- 後続文が前文の理由なのに「〜からです」「〜ためです」がない
- 換言・補足なのに「つまり」「言い換えると」がない
- チェック: 各文について前文との関係（理由・具体化・換言・対比・並列）を判定し、理由・換言で標識がなければ補う

過剰型（note・バズ記事型）:
- 「つまり」「そして」「でも」「だから」が段落ごとに出る
- 「つまり」は1記事2回まで。接続詞なしで論理が通る箇所からは削る

### B-10. 文体混在（両方向）

- 敬体基調への常体挿入（「コードは書かない。」「気にしなくていい。」）: 原則0回。演出は引用・独立行のみ
- 常体基調への敬体挿入（「ただの過積載です。」「〜なんですよね。」）: 同じく原則0回
- 検出: 全文末の形態を分類し、基調（過半数側）と異なる文末をフラグする。機械検出が最も容易

## セルフチェック指示文（プロンプト貼り付け用・v0.3版）

```
執筆後、出力前に以下を順に確認すること。

1. [対比] 「ではなく」「ではありません。」「じゃない。」を数える。
   3回以上なら、肯定形だけで主張が立つ箇所を畳んで2回以下にする。
   冒頭と結末が同じ対比の反復（円環）になっていたら、結末を別表現に変える。
2. [語彙] 効く・刺さる・溶ける・食う・汚れる・ブレる・潰す・回す等の
   転用を数える。1,000字1回超過分と、同一動詞の2回目以降を標準語彙に置換。
   見出し・リード・結論は0回にする。
3. [比喩] 記事内のメタファーを系統別に列挙する。2系統以上あれば、
   主張に直結する1系統だけ残して他を事実記述に開く。残した系統も反復3回まで。
4. [反復] 同語尾3連続（三連反復）と同型の節末締めを検出し、
   3つ目・2節目以降の形を崩す。
5. [予告] 「ここが大事」「〜の話をします」型のメタ談話予告を検出し、
   1回を残して削除する。「するとどうなるか？」型の自問自答も同様。
6. [接続] 各文と前文の関係を確認する。理由なのに「からです」がない、
   換言なのに「つまり」がない箇所を補う。逆に「つまり」が3回以上なら削る。
7. [文末] 全文末を走査し、基調と異なる文体（敬体中の常体、常体中の敬体・
   「なんですよね」）を統一する。体言止めは3回以内・連続なし。
8. [強調] 決定的・本命・かなり・正直等の強調語で同一語2回以上を言い換える。
9. [記号] 「——」を数え、3回以上なら括弧・読点・「つまり」に開く。
10. [慣用句] 慣用句使用箇所の原形を確認する（的を射る・頭ひとつ抜ける等）。
```

## lint実装優先順位

1. B-1 対比構文カウンタ: 正規表現で即実装可能、全検体で最重度、費用対効果最大
2. B-10 文末混在チェッカー: 正規表現＋活用表で実装容易、確度が高い
3. B-5／B-7／A-4: 固定文字列・固定パターン。既存lintに追記するだけ
4. B-2 三連反復: 文末n-gramの3連続一致で検出可能
5. A-1／A-3: 形態素解析＋密度計算。MeCab/Sudachi
6. B-6／B-8: 半機械（パターン＋位置情報）
7. B-9 談話接続: 機械検出不可。単機能プロンプト（談話接続の欠落のみ指摘させる）の2パスLLMレビューで対応。観点を1つに絞るのが精度の鍵
